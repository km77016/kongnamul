# AIRMRKT 백엔드

에어팟(Pro1/Pro2/Pro3/AirPods4 노캔) 리셀 마켓의 실제 작동하는 백엔드 + 관리자 대시보드입니다.
Flask + SQLite로 만들어졌고, 모든 핵심 흐름을 로컬에서 직접 실행해 curl로 검증했습니다.

## 실제로 확인된 것 / 안 된 것

✅ **여기서 실제로 실행·검증함**
- 회원가입 → 이메일 인증코드 발급/검증(오답·만료·재요청 쿨다운·시도횟수 제한) → 가입 시 잔액 **0원**
  시작 → 로그인 → 세션 유지 → 로그인 필요 API 보호(비로그인 시 401)까지 전체 흐름
- **계좌이체 충전**: 충전 요청 생성(참조코드 발급) → 관리자 승인 → 잔액 반영까지 실제 흐름
- **매입 신청(검수 기반 판매)**: 신청 → 관리자 수령확인 → 검수(최종등급 확정, 가격 재계산)
  → 정산승인 → 지급까지 전체 파이프라인. 자가진단 등급과 실제 지급액이 다르게 계산되는 것까지 확인
- **구매**: 검수완료 재고 구매(즉시), 배송/보관 선택, 제주·도서산간 배송비 할증
- **보관료**: 30일 무료 후 월 2,000원 — 40일 경과 상황을 강제로 만들어 계산 검증
- **관리자 대시보드**(`/admin`): 로그인, 수익현황, 주문내역, 계정정보, 매입신청 관리, 입금확인,
  계좌관리, 감사로그 — 전 메뉴 API를 curl로 호출해 200 응답 확인
- **보안**: CSRF 토큰 없이 상태변경 요청 시 403 차단, 로그인 5회 실패 시 15분 잠금, IP당 요청
  빈도 제한(rate limit), 관리자/일반회원 권한 분리, 감사로그 기록까지 실제로 트리거해서 확인
- 전체 여정 하나로 묶어서 검증: 가입(0원)→충전승인→구매→매입신청 전체처리 후 최종 잔액이
  계산과 정확히 일치하는지 확인함
- **동시성**: 재고 3개 상태에서 10명이 동시에 구매를 시도하는 실제 부하 테스트를 돌려서, 정확히
  3건만 성공하고 나머지는 정상적으로 "품절" 처리되는 것을 확인함 (오버셀링 없음)
- **리뷰**: 구매 완료 → 리뷰 작성 → 중복 작성 차단 → 이메일 마스킹까지 curl로 전체 흐름 검증함
- **DB 자동 마이그레이션**: 앱 폴더 안에 구버전 market.db를 만들어놓고 새 코드로 실행해서, 홈 폴더의
  새 위치로 자동 복사되는 것까지 실제로 확인함
- **실시간 알림(SSE)**: 실제로 SSE 연결을 열어둔 채 관리자가 잔액을 조정했을 때, 몇 초 안에 알림
  이벤트가 도착하는 것을 스트리밍 응답으로 직접 확인함

❌ **여기서는 실행/검증이 원천적으로 불가능했음** (이 작업환경 자체의 네트워크 제한 때문)
- `scraper.py`가 실제 중고나라/번개장터에 접속하는 부분 — 이 환경은 외부 HTTP 요청이
  `Host not in allowlist`로 전부 차단됩니다.
- **실제 이메일 발송(SMTP)** — DNS는 되지만 소켓 연결 자체가 막혀있어(`Address family not
  supported by protocol`) smtp.gmail.com:587 접속을 시도조차 못 했습니다. `.env`에 넣어둔
  실제 Gmail 계정/앱 비밀번호로 이 코드가 동작하는지는 **사용자님 컴퓨터/서버에서 확인해주셔야
  해요.** 코드 로직(제목/본문 생성, 로그인, 발송 호출) 자체는 표준적인 smtplib 사용법이라
  정상적인 네트워크 환경에서는 그대로 작동할 거예요.
- 이 서버를 실제 인터넷에 호스팅하는 것 (배포), 그리고 진짜 디도스 공격에 대한 방어(아래
  "보안과 디도스" 항목 참고)
- **토스페이먼츠 결제 승인 API 호출** — `/api/pg/success`가 `api.tosspayments.com`에 결제 승인을
  요청하는 부분은 네트워크가 막혀 있어 실제로 호출해보지 못했습니다. 요청은 토스 공식 문서 형식
  그대로 만들었고, 이 API가 실패해도(또는 접속 자체가 막혀도) 서버가 죽지 않고 결제 실패로 안전하게
  처리되는 것까지는 확인했어요.

## ⚠️ 중요: 데이터베이스는 이제 앱 폴더 밖에 저장돼요

예전 버전은 `market.db`가 `app.py`와 같은 폴더에 있었어요. 그래서 새 zip을 받아서 폴더를 덮어쓰면
(특히 폴더 전체를 지우고 새로 압축을 풀면) **데이터가 통째로 사라지는 문제**가 있었어요.

지금은 기본적으로 **`~/kongnamul_data/market.db`** (홈 폴더 밑, 앱 폴더 완전히 바깥)에 저장돼요.
앱 폴더를 몇 번을 덮어써도 이 데이터는 안전해요.

**기존에 앱 폴더 안에 `market.db`가 있었다면** 서버를 처음 실행하는 순간 자동으로 새 위치로
복사되고, 콘솔에 "기존 market.db를 발견해서..." 라는 안내가 떠요. 예전 파일은 확인 차원에서
그대로 남겨두니 안심되면 나중에 직접 지우셔도 돼요.

저장 위치를 직접 지정하고 싶으면 `.env`의 `AIRMRKT_DB_PATH`를 채우세요.

관리자 대시보드 "시스템" 탭에서 언제든 **지금 실제로 어떤 DB 파일을 쓰고 있는지** 경로·크기·수정시각을
확인할 수 있어요. "분명히 추가했는데 사라졌다" 싶으면 여기부터 확인하세요.

## 1. 로컬에서 실행하기

**Windows에서는 `start.bat`을 더블클릭하면 끝이에요.** Python 설치 여부를 확인하고,
필요한 패키지를 자동으로 설치한 뒤 서버를 켜고 브라우저까지 자동으로 열어줍니다.
서버가 켜진 검은 창은 로그가 나오는 창이라 닫으면 서버도 같이 꺼져요. 그대로 두세요.
관리자 화면만 다시 열고 싶을 땐 `open_admin.bat`을 더블클릭하세요 (서버가 이미 켜져 있어야 해요).

Python이 없다면 [python.org](https://www.python.org/downloads/)에서 설치할 때
**"Add Python to PATH"** 체크박스를 꼭 켜주세요. 안 켜면 `start.bat`이 Python을 못 찾아요.

macOS/Linux나 터미널을 직접 쓰고 싶다면:
```bash
cd airpods_backend
pip install -r requirements.txt
python app.py
```
브라우저에서:
- 고객 사이트: `http://localhost:5000`
- 관리자 대시보드: `http://localhost:5000/admin`

서버를 처음 실행하면 콘솔에 **초기 관리자 계정(username: admin, 임의 비밀번호)**이 한 번 출력돼요.
지금 기록해두세요 (다시 표시되지 않아요). 원하는 값으로 고정하려면:
```bash
export AIRMRKT_ADMIN_USER=admin
export AIRMRKT_ADMIN_PASS=원하는비밀번호
```

## 2. 이메일 발송 설정 (.env)

`.env` 파일에 실제 Gmail 계정 정보를 넣어뒀어요 (`mint.team2026@gmail.com` + 앱 비밀번호).
서버가 시작할 때 자동으로 이 파일을 읽어서 환경변수로 설정합니다 (외부 라이브러리 없이 직접 구현).

⚠️ **`.env` 파일은 실제 비밀번호가 들어있는 파일이에요.**
- 절대 깃허브 등에 커밋하거나 공유하지 마세요 (`.gitignore`에 이미 등록해뒀어요)
- 이 앱 비밀번호가 조금이라도 찜찜하면, 구글 계정(myaccount.google.com → 보안 → 앱 비밀번호)에서
  아무 때나 무료로 폐기하고 새로 발급할 수 있어요
- `.env` 없이 실행하면 자동으로 DEV MODE로 동작해서, 인증코드가 화면에 바로 표시돼요
  (실제 메일함 없이 테스트 가능)

`.env` 내용:
```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=mint.team2026@gmail.com
SMTP_PASS=xgmy opqa nenl dmvu
```

세션 키는 서버를 재시작할 때마다 랜덤 생성돼서 기존 로그인이 풀립니다. 운영에서는 고정하세요:
```bash
export AIRMRKT_SECRET_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")
```

## 3. 매입(판매) 플로우 — 검수 기반으로 설계됨

즉시 매도 버튼 대신, 실제 운영과 같은 검증 단계를 거칩니다.

```
① 매입 신청 (자가진단 등급 선택, 예상가 표시)
② 관리자: 수령확인 (실물 도착 확인)
③ 관리자: 검수 완료 (실측 최종등급 입력 → 가격 재계산)
④ 관리자: 정산 승인 → 그 순간 잔액 지급
```

자가진단 등급과 실제 검수 등급이 다르면 최종 지급액도 달라져요 (예: 사용자는 A급이라 신고했지만
실제로는 S급이라 더 많이 지급되는 경우도, 반대의 경우도 실제로 재현·검증했습니다). 각 단계에서
관리자는 반려도 할 수 있고, 사용자는 배송 전(`submitted` 상태)에만 신청을 취소할 수 있어요.

## 4. 잔액 충전 — 계좌이체 + 관리자 승인

- 사용자가 충전 금액을 입력하면 참조코드(`AM-XXXXXX`)가 발급되고, 현재 활성 계좌 정보가 표시돼요
- 사용자는 입금자명에 참조코드를 포함해 이체 → 관리자가 실제 은행 내역과 대조해서 승인/거절
- 승인하는 순간 해당 사용자 잔액에 반영돼요

**계좌를 여러 개 두고 자주 rotation 하는 방식은 일부러 넣지 않았습니다.** 여러 계좌로 입금을
분산시켜 이체한도를 피하는 방식은 의도와 무관하게 보이스피싱 대포통장·불법 도박사이트가 자금
추적을 피할 때 쓰는 방식과 같아서, 은행의 이상거래 탐지 대상이 되고 계좌가 정지될 위험이 커요.
대신 **활성 계좌 1개 + 예비 계좌 등록/전환** 구조로 만들었어요 (은행 점검 등 정당한 사유로 계좌를
바꿔야 할 때 관리자가 전환). 거래량이 늘면:
- **PG사 가상계좌** (토스페이먼츠, 나이스페이, KG이니시스 등) — 고객별 자동 가상계좌 발급, 한도 문제 없음
- **사업자 통장 전환** — 개인 계좌보다 이체한도가 훨씬 높음

둘 중 하나로 전환하는 걸 권장해요.

## 5. 관리자 대시보드 (`/admin`)

| 메뉴 | 기능 |
|---|---|
| 수익현황 | 매입/판매 스프레드, 배송비·보관료 수익을 오늘/전체 기간으로 집계 |
| 주문내역 | 최근 체결 거래 (구매자 이메일 포함) |
| 계정정보 | 가입 회원, 잔액, 보관중 수량, 거래횟수 |
| 매입신청 | 상태별 필터, 수령확인/검수확정/정산승인/반려 처리 |
| 입금확인 | 대기중인 계좌이체 요청 승인/거절 |
| 계좌관리 | 입금 계좌 추가 및 활성 계좌 전환 |
| 감사로그 | 관리자 조치 + 로그인 실패 등 보안 이벤트 기록 |
| 시스템 | 수동 시세갱신, 전체 초기화(2단계 확인 필요) |

## 6. 판매 시간창(드랍) · 예약 · 상품 관리 · 동시성

- **상품 관리**: 관리자 대시보드 "상품관리" 탭에서 새 상품(모델)을 등록하거나, 노출/숨김을 전환할 수 있어요.
  등록 직후엔 재고 0개라 "재고관리" 탭에서 수량을 채워야 실제로 노출·구매가 가능해요.
- **드랍(판매 시간창)**: 상품별로 판매 시작/종료 시각을 지정하면, 그 시간 밖에서는 구매 요청 자체가
  서버에서 차단돼요(400 응답). 프론트엔드는 카운트다운 배너를 보여주고 시간이 될 때까지 구매 버튼을
  비활성화해요.
- **예약**: 드랍 시작 전에 사용자가 "예약 알림 받기"를 누르면 관심 등록만 되고(재고를 미리 잡아두지는
  않아요), 사이트 방문 시 판매 상태를 바로 확인할 수 있어요.
- **동시성(오버셀링 방지)**: 재고 차감은 `UPDATE stock SET qty=qty-1 WHERE qty>0` 형태의 **조건부 원자적
  UPDATE 한 번**으로 처리해요. 실제로 재고 3개 상태에서 10명이 동시에 구매를 시도하는 테스트를 돌려서
  정확히 3명만 성공하고 나머지는 "방금 품절됐어요"로 실패하는 것까지 확인했어요 (race condition 없음).
  드랍 순간의 연타 대비로 `/api/trade`에 IP당 요청 빈도 제한도 걸려 있어요.
- **보관 위험 알림**: 보관 중인 아이템의 누적 보관료가 현재 매도가의 70%(경고)·100%(위험) 이상이 되면
  자동으로 이메일 발송을 시도하고(실제 발송 여부는 SMTP 설정에 따름), 보관함 화면에도 배너로 표시돼요.
  시세 갱신 배치(`do_tick`)가 돌 때마다 함께 점검해요.

## 7. 리뷰 · 실시간 알림 · 카드결제 · 법적 페이지

- **리뷰**: 실제로 구매를 완료한 거래(trade)에 연결된 리뷰만 작성할 수 있어요. 한 거래당 리뷰 1개,
  중복 작성은 서버에서 막아요. 공개 리뷰 목록에서는 이메일이 `re***@test.com` 형태로 마스킹돼요.
  관리자는 "리뷰관리" 탭에서 부적절한 리뷰를 삭제할 수 있어요.
- **실시간 알림(SSE)**: 이 샌드박스에는 Flask-SocketIO 같은 웹소켓 라이브러리를 설치할 수 없어서
  (외부 네트워크 차단), 대신 순수 Flask만으로 되는 **Server-Sent Events**로 구현했어요. 매입신청 처리,
  입금 승인/거절, 잔액 조정, 계정 정지, 강제매각, 새 공지사항 등록 시 로그인한 유저에게 실시간으로
  토스트 알림이 뜨고 필요하면 화면이 자동 새로고침돼요. 실제로 서버를 띄우고 SSE 연결을 열어둔 채
  관리자가 잔액을 조정하면 몇 초 안에 알림이 도착하는 것까지 확인했어요. (`app.run(threaded=True)`로
  동시 연결을 지원해요.)
- **카드/간편결제 충전(토스페이먼츠)**: 계좌이체 외에 카드로 즉시 충전할 수 있어요. 문서에 공개된
  범용 테스트 키가 기본값으로 들어있어서 별도 설정 없이 결제창까지는 테스트할 수 있어요. 다만 **실제
  결제 승인 API 호출(`/api/pg/success`가 토스 서버에 확인 요청을 보내는 부분)은 이 샌드박스의 네트워크
  차단 때문에 검증하지 못했어요.** 요청 형식은 토스 공식 문서 그대로 구현했고, 실패해도 서버가 죽지
  않고 결제 실패로 안전하게 처리되는 것까지는 확인했어요. 실결제로 전환하려면 `.env`에 본인 상점의
  `TOSS_CLIENT_KEY`/`TOSS_SECRET_KEY`를 넣으세요.
- **이용약관 · 개인정보처리방침 · 사업자정보**: 고객 사이트 하단 푸터에 링크가 생겼어요. 약관/방침은
  전자상거래에서 흔히 쓰는 **템플릿**이니 실 서비스 전에 반드시 법률 검토를 받으세요. 사업자정보는
  관리자 대시보드 "사업자정보" 탭에서 입력하면 바로 반영돼요.

## 8. 단골등급 · 가격알림 · 찜하기 · 휴대폰인증 · 관리자알림 · 검색/인기상품

- **단골 등급제**: 완료된 거래 횟수 기준 브론즈(0)/실버(5+)/골드(15+)/플래티넘(30+)로 자동 승급되고,
  등급이 높을수록 매입·판매 스프레드가 0.5~1.5%p 할인돼요. 실제로 5번 거래시켜서 실버로 승급되고
  구매가가 낮아지는 것까지 확인했어요.
- **가격 알림**: 원하는 가격 이하로 떨어지면 알려달라고 설정하면, 시세 갱신 배치(`do_tick`)가 돌
  때마다 조건을 검사해서 실시간 알림(SSE)으로 쏴줘요.
- **찜하기**: 품절된 상품을 찜해두면, 재입고되는 순간(관리자 수동 입고/매입정산 자동편입/랜덤 재입고
  전부 포함) 알림이 가요.
- **휴대폰 본인인증**: 이메일 인증과 동일한 구조(발급→검증)예요. 실제 SMS 게이트웨이(알리고 등)는
  유료 계약이 필요해서 기본은 DEV MODE로 동작하고, `SMS_API_KEY`를 설정하면 실제 발송 코드를 넣을
  자리(`send_sms()` 함수 안 TODO)가 마련돼 있어요.
- **관리자 실시간 알림**: 새 매입신청·새 충전요청·품절·매각위기 발생 시 관리자 대시보드에도 SSE로
  즉시 알림이 떠요. 유저용과 별개의 채널(`/api/admin/stream`)이에요.
- **검색 + 인기상품**: 마켓/구매하기 화면에 검색창이 생겼고, 최근 7일 거래량 기준 인기상품 배너가
  마켓 화면 상단에 떠요.

## 9. 보안 — 실제로 적용하고 검증한 것들

- **CSRF 방어**: 로그인 시 발급되는 토큰을 모든 상태변경 요청(`X-CSRF-Token` 헤더)에 붙이지
  않으면 403으로 차단
- **로그인 브루트포스 방어**: 계정당 5회 실패 시 15분 잠금 (일반회원/관리자 둘 다 별도 적용)
- **앱 레벨 요청 제한(rate limit)**: 로그인·인증코드 발송·충전 요청 등 민감한 엔드포인트에
  IP당 시간당 호출 횟수 제한
- **세션 쿠키**: HttpOnly 항상 적용, `AIRMRKT_FORCE_HTTPS=1` 설정 시 Secure 플래그도 추가
- **보안 헤더**: X-Content-Type-Options, X-Frame-Options, Content-Security-Policy, Referrer-Policy
- **권한 분리**: 회원 세션과 관리자 세션이 분리된 키로 관리되고, 관리자 전용 API는 전부
  `admin_required`로 보호
- **감사로그**: 로그인/로그인실패/입금승인/매입처리/계좌변경/초기화 등 모든 민감 조치 기록

### 보안과 디도스에 대해 정직하게 말씀드릴게요

**진짜 디도스(대량 트래픽) 공격은 애플리케이션 코드만으로 막을 수 없어요.** 이건 이 프로젝트의
한계가 아니라 일반적인 사실이에요 — Flask든 어떤 프레임워크든 마찬가지입니다. 실제로 막으려면:

1. **Cloudflare, AWS Shield 같은 CDN/WAF를 도메인 앞단에 반드시 두세요** (무료 플랜도 기본적인
   디도스 방어를 제공해요). 이게 사실상 유일한 진짜 방어선이에요.
2. 이 앱에 넣은 rate limit은 그 앞단이 뚫렸을 때의 2차 방어선이자, 무엇보다 **브루트포스 로그인
   시도 방지용**이에요. 여러 프로세스로 운영하면 프로세스마다 카운터가 따로 놀기 때문에, 트래픽이
   커지면 Redis 기반(Flask-Limiter + Redis)으로 교체하세요.
3. 프로덕션 배포 시 Flask 개발서버(`python app.py`) 대신 gunicorn/uWSGI + nginx 조합을 쓰고,
   nginx에서도 `limit_req` 같은 자체 제한을 걸어두면 좋아요.

## 10. 외부 시세 참고값 갱신하기

**A. 수동으로 (관리자 세션 필요)**
```bash
curl -c admin_cookies.txt -X POST http://localhost:5000/api/admin/login \
  -H "Content-Type: application/json" -d '{"username":"admin","password":"위비밀번호"}'
# 응답의 csrf_token을 아래에 사용
curl -b admin_cookies.txt -X POST http://localhost:5000/api/external_ref \
  -H "Content-Type: application/json" -H "X-CSRF-Token: 위csrf_token" \
  -d '{"pro2": {"avg": 155000, "note": "오늘 확인한 시세"}}'
```

**B. 스크래퍼로 자동화 (인터넷 되는 본인 환경에서 테스트 필요)**
```bash
python scraper.py                 # 1회 수집
python scraper.py --loop 28800    # 8시간마다 반복
```
스크래퍼 코드도 관리자 로그인 후 세션 쿠키로 `/api/external_ref`를 호출하도록 업데이트해야
합니다 (현재는 인증 없이 호출하는 예시 코드라, admin 로그인 단계를 추가해서 쓰세요). 실제 사이트
구조를 검증한 적이 없어서 셀렉터/정규식은 직접 확인 후 조정하세요.

## 11. 실제 배포하고 싶다면

- **가장 쉬운 방법**: Render.com, Railway.app, Fly.io 같은 PaaS + `gunicorn app:app`
- **직접 서버 운영**: VPS + nginx + gunicorn, 앞단에 Cloudflare
- **데이터베이스**: 지금은 SQLite 파일 하나라 소규모엔 충분하지만, 트래픽이 늘면 PostgreSQL 권장
- **스크래퍼 스케줄링**: `scraper.py --loop`을 상시 실행하거나 cron/systemd timer 등록

## 12. 스크래핑 관련 법적 주의사항

중고나라·번개장터·당근마켓은 각자 이용약관에 자동 수집 관련 조항이 있을 수 있습니다. 운영 전에
이용약관과 robots.txt를 확인하고, 필요하면 공식 제휴/API 제공 여부를 문의하세요.
